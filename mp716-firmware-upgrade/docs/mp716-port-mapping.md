# MP716 物理网口逐口实测

2026-11-19，在运行 1.0.6 的这一台 MP716 上完成。用户明确机壳标签，按 LAN4→LAN3→LAN2→LAN1 依次搬动电脑网线；随后仅拔下 WAN 约 60 秒并插回。所有采样通过固定主机密钥的 SSH、有线接口 9 和原管理地址完成，没有写交换机配置或刷机。

| 机壳标签 | 内部交换机端口 | 实际逻辑 VLAN |
| --- | --- | --- |
| LAN1 | P0 | 1 |
| LAN2 | P1 | 1 |
| LAN3 | P2 | 1 |
| LAN4 | P3 | 1 |
| WAN | P4 | 2 |

每次搬线均且仅出现一个端口下降、一个端口上升，其他链路、速率和 VLAN 不变。WAN 拔下和插回时，仅 P4 分别下降和上升。前后设备身份、SSH 密钥和 boot 相同。P6 是 CPU 口；P5 在该机当前配置中禁用，未作为外壳网口。驱动没有 ARL 查询属性，未拿不可用的 MAC 表作证据。

采样结束后，用户已将电脑接回原 LAN4，WAN 接回原口。此结果只确认本机的外壳映射，不代替 UART、GPIO、RAM 启动、恢复路径或 VPN 验收，不将整个固件的 UNVERIFIED/生产升级门状态改为通过。

新版原生模块 `physical-ports.uc` 读取可选的 `/etc/mp716-admin/port-map.json`：

- 校准与板名 `yunxm,mp716`、本机 board.json 的 LAN MAC 绑定，不能把本机文件当作所有 MP716 的公共默认值。
- 标签及端口必须唯一，每条须有人工核验标记和至少两份不同的 SHA256 证据；错误设备、重复或无证据的记录全部拒绝。
- 未校准时保留 P0–P4，角色为 unknown；交换机读取失败时返回未知链路，不伪装成拔线。
- 五个端口均有有效校准才设置 `physicalLanOrderVerified=true`，不改变其他硬件或固件测试标记。

配套前端处理三态链路并保留原厂适配器兼容行为。修改在源码中；尚未通过新镜像部署到设备，现机不会因为离线生成文件自动改变显示。

本机私有证据在 `build/hardware-vpn-106/20261119-172301-59d322f3/`：`port-samples/`、各步映射报告、`map-complete.json`，以及从完整证据导出的设备专属 `port-map.json`。没有向设备写入该校准文件。原完整配置归档也保留在此目录，不进入公共发布包。

校准目录已在 sysupgrade keep.d 的 `/etc/mp716-admin/` 保留范围内。旧的手动升级辅助脚本只白名单保留 access.json，后续使用前必须加入 port-map.json；网页普通配置备份当前不包含物理校准，应单独保管设备校准文件。
