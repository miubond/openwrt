## 已确认缺陷：P1 VPN 启动 JSONPath 错误

1.0.5 冻结产物的 `integration/ram-web/mp716-vpn.init:9` 使用：

```sh
/usr/bin/jsonfilter -i "$runtime/services.json" -e "@$1"
```

展开后得到 `@pptp`、`@l2tp`、`@ipsec`、`@openvpn` 等非法表达式；对象属性表达式应使用 `@.$1`。真机日志实际记录了 `Syntax error: Expecting End of file`，不是推测问题。

六种运行标志及 `guard`、`chap` 都受影响：VPN procd 实例/客户端启动分支不执行；解析失败被当成空 guard，可能错误删除专属防护表。启用服务器、OpenVPN 或 IPSec 通常会被后续健康检查发现并回滚；单独 PPTP 客户端不要求服务实例，仍可能只保存成功而未连接。

现有 shell 编排测试重定义 `json_value()`，绕过真实 jsonfilter，因而漏检。后续修复需同时补正确 JSONPath、读取失败的安全处理、真实 jsonfilter 正反例；不能简单隐藏标准错误。

本轮保持所有 VPN 关闭，未向设备部署修复、未重启 VPN、未刷入新镜像。**VPN 运行和远端互通未通过实机验收。**

## 终端 ACL 数据面验收方案与当前限制

本地独立辅助脚本：`build/github-44443686119/settings-105/wlan-probe.py`。脚本生成及语法检查不代表探针成功；首次临时 WLAN 关联未成功，随后自动清理通过，没有进行 ACL 上锁或解锁。不能把此前升级后的 Wi-Fi 连通证据挪用为本轮 ACL 结果。

本地只读检查未发现选错网卡、目标 BSSID 大小写或脚本工程路径错误；但该次探针没有逐次关联明细，无法仅凭保存的 connecting 状态把原因归咎于认证、扫描或 DHCP。

随后在导航 `about:blank` 时，Computer Use 返回“could not determine current browser URL with enough confidence”，因此本轮停止新增 GUI 操作，没有绕过工具限制。停止原因不是用户干扰；也不能把工具停止记为路由器后台故障。不通过反复切网或更改设备设置扩大排查范围。

探针要求：

1. 切换前即时记录 Windows 当前 WLAN profile/关联状态、IP配置与原 profile 集，不复用旧记录。
2. 只添加唯一的临时当前用户 profile，密码 XML 仅在内存传递，不覆盖原 profile。
3. 保持有线管理 ifIndex 9，Wi-Fi 网卡使用实际识别的另一接口及其 MAC/IP；所有探测 socket 显式绑定接口和源地址。
4. 先证明 Wi-Fi 和有线均能通过同一固定外网目标；再由 GUI 只上锁探针自己的 Wi-Fi MAC。
5. ACL 只作用于转发，故阻断阶段路由器管理 HTTP 和路由器 DNS 应继续可达；要求三个新的 Wi-Fi TCP 连接均失败，而同目标有线流量前后成功。
6. ACL add/remove 会重建 nft 表并重置计数；应在添加后记录计数基线，再检验探测导致的 drop 增量。
7. GUI 移除该 MAC 后，同一 Wi-Fi 路径恢复；最后还原 PC 原 WLAN 关联/断开状态并删除唯一临时 profile。
8. 原 `access.json` 若不存在，单纯 GUI 移除可能留下空数组文件；最终由控制器恢复原文件存在状态，并复核原 nft 阻断集合。

上述方案留待之后有条件时执行，本轮终端数据面测试记为 NOT COMPLETED。故障清理已完成；没有实际添加的测试 MAC 需要移除。不通过禁用网卡、更改路由优先级或刷机解决测试障碍。
