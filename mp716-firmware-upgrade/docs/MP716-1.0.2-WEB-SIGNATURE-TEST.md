## 网页实际结果

从 MP716 新版 Vue 后台登录，通过系统文件选择框选中上述原包，点击“上传并校验”。页面实际显示：

- **签名验证通过**。
- 包版本不高于当前版本，版本检查未通过，未执行升级。
- `signature_checked: true`。
- `code: 14`，`error: downgrade`。
- `flash_write: false`、`bytes_programmed: 0`、`erased: false`、`upgraded: false`。
- `accepted: false`、`ok: false`；原生整体检查没有被伪装成成功。

设备实际安装版本和包版本均为 1.0.2，原生引擎正确拒绝同版本升级。签名有效与可接受升级是两个独立结果，前端现在保留并展示原生结果和原始 JSON。没有清空装机版本或启用强制降级来绕过检查。

原生版本检查先于负载结构检查；本次同版本拒绝时，`squashfs_offset: 0`、`uimage_name: ""` 不代表已完成真机负载结构核验。离线结构检查通过。原生 `check` 报告中的 `custom_firmware_installed: false` 没有填入运行配置状态，不应据此判断设备未安装自研固件；已单独读取 `/etc` 和 `/rom` 的设备配置确认运行版本为 1.0.2。

## 保留配置与测试记录

安装公钥前备份现有配置、密码、设备版本配置、原生上传服务和验签配置。测试后对原配置、密码、设备版本配置及 boot ID 做字节比较。私有备份与完整原始响应存放在被忽略的 `build/full-admin/key-verification/`，不提交登录凭据。

最终比对全部一致，没有重启。另将包签名末尾一位临时翻转后经同一真实 HTTP 接口发送，服务返回代码 10、`signature_checked: false`，正确拒绝无效签名；原文件未修改。正反两项测试均为 `flash_write: false`、`bytes_programmed: 0`，生产刷写开关仍关闭。

前端类型检查、生产构建及 8 项单元测试通过。新测试覆盖版本拒绝仍为整体失败、保留有效签名证据、无效签名不得显示为安全版本拒绝、异常成功响应不得冒充整体校验通过。
