# 恢复计划

MP716 还没有验证过可靠的串口恢复，也没有 A/B 分区。防变砖在这里只表示四件事：

1. 写入前做严格校验。签名、型号、硬件修订、原厂代际、降级策略、长度、哈希和镜像结构没有全部通过时，不进入编程。
2. 限制写入范围。模拟后端只能改已经存在、长度正好是 firmware 分区、并且以 `.fakemtd` 结尾的文件。Bootloader、Config、Factory 和调用者传入的 MTD 路径都不能成为目标。
3. 减少升级风险。上传完成、校验完成和模拟编程完成都不是升级成功。掉电或 IO 错误停在 `FAILED`，并保持 `unrecoverable=true`。
4. 提供可重复的人工恢复路径。操作者另外保存一份 firmware 分区的离线副本，失败后显式执行 `recover`。程序不会在失败时自己把旧内容写回去。

这不是“升级失败一定自动回滚”。单分区被擦除之后，旧固件已经不在那块分区里，代码也不会报告它还在。

## 开发机上的人工恢复

`recover` 不在 CGI 里。网页不能触发它。

命令只接受 `--backend fake`。已知良好镜像必须是另一份普通文件，长度正好 8,060,928 字节；它不能是 `.fakemtd`，也不能是 `/dev/mtd`。程序先按块计算它的 SHA-256，再擦除并编程模拟分区，最后读回比对。哈希不一致就保持 `FAILED`。

一次恢复如果再次被掉电打断，分区仍然不可用。操作者排除故障后可以再执行同一条命令。读回匹配之后状态回到 `IDLE`，待升级版本被清掉，`upgraded` 仍是 false。设备配置文件里的原厂版本和自研版本都不改。

因此开发机能够演示的是：失败不会伪装成成功，同一份离线副本可以再次写回模拟分区。它不能证明路由器在断电后会自己启动旧系统。

## 测试机之前

串口菜单、TFTP 和原厂固件恢复演练都还没有记录。真实 MTD 后端保持禁用，`--allow-flash-upgrade` 会直接拒绝。

第一阶段先要在开发机上通过这四项：

- 独立生成 `.mp716upd`
- 验证签名
- 模拟固件写入
- 模拟失败后的人工恢复

这四项通过，才进入测试机的安装与升级验收。验收开始之前，仍要先完成同机备份、串口确认和原厂固件恢复演练。当前还没有进入这一步。
