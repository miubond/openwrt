# MP716 1.0.7 候选修复与构建记录

日期：2026-11-20。源码版本已调整为 **1.0.7**；完整 Linux 镜像构建及产物核验尚待执行。路由器仍运行 1.0.6，原 53 项配置及四处临时代码挂载已恢复，本阶段不刷机。

基线是实际构建 1.0.6 的 `15c720c0f1d0e7bc51b0e5e1d497d145e9480b85`。继续固定 OpenWrt 25.12.6 / `64900e756efa667774214f9c6b17c113222e01f7`，不改内核、DTS、保护分区或升级业务逻辑。

## 本候选包含的修复

- VPN 设备型防火墙区省略空 `network` 列表，保留非空接口配置。
- PPTP 使用 `noipparam` 保留受管 PPP 会话类型钩子。
- 修正 VPN 明文保护规则的 NFT 结束分隔符。
- L2TP 只由受管选项要求 MSCHAPv2，使用 `[lns default]` 匹配入站测试对端。
- 固定 strongSwan 6.0.7 GMP/DH 插件使用正式版本导出宏，并保留源依赖及内核加密依赖。
- 网口无法读取链路时显示“未知”。修改已回补至主前端 `openwrt_system` 的 `bbf6d4618fd6b0e4faf5ea1c8e6cc8d60fb283ba`，再正常导出 167 项源码，未直接修改来源清单。

## 交付检查

RAM 插件检查从最终 uImage 内的 CPIO 读取，LAN 插件从最终 sysupgrade 的 squashfs 读取；不以构建树中的单独文件替代交付镜像。物理端口模块也须从最终镜像读取并与源码逐字匹配。发布时核对 ABI 报告成功状态、固定源码提交、镜像类型、原生文件名和实际 SHA256，拒绝旧报告与新镜像混用。重建前清除候选成功标记，独立工具链缓存继续保留。构建脚本保持与 1.0.6 相同的工具链 key 输入，缓存实际命中以本次 CI 日志为准。

版本发布目录保持 `releases/1.0.7/targets/ramips/mt76x8/`，附带硬件、网口及限定 VPN 互通报告和总 SHA256。GitHub/Gitea 失败产物保留镜像检查 JSON 和日志。原 `.mp716upd` 签名格式、配套测试公钥机制及 `UNVERIFIED` / 关闭的生产在线升级状态不变。

## 当前验证范围

主前端 192 项测试、TypeScript 与 OpenWrt Web 构建通过。VPN 渲染修复已有真实 MIPS 的 37 项回归，以及原 1.0.6 加受控 RAM 修复的 OpenVPN 客户端、PPTP 服务端、L2TP/IPsec 服务端限定场景互通记录，详见 [VPN 报告](mp716-vpn-interoperability.md)。这些记录不代表尚未生成的 1.0.7 完整镜像已通过启动、升级或生产验收。

完整镜像仍须完成 Linux CI 构建、下载后的镜像与报告 SHA256、实际 rootfs 源码及 GMP/DH ABI 核验、签名容器与 sysupgrade 载荷一致性检查。未执行设备端上传、升级或重启。
